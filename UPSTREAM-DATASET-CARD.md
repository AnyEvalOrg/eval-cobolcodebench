CobolCodeBench is an evaluation dataset of 46 Cobol programming tasks adapted from BigCodeBench-Hard. <br>
It's designed to benchmark code completion and code generation capabilities for legacy Cobol systems.

## Github
For Source code and results analysis, check out our [github](https://github.com/CobolCodeBench/CobolCodeBench-Framework.git).

## Purpose

The Dataset has the following purposes:
1. **Benchmarking**: To provide a standardized evaluation framework for LLMs on COBOL code generation and completion tasks.
2. **Research**: To explore the capabilities and limitations of LLMs in handling legacy programming languages.


## Dataset Structure

### Instruction_Set

**Program_name**: The name of the COBOL program or task being evaluated. <br>
**instruct_prompt**: Prompt with detailed description of the COBOL program requirements, including functionality, structure, and coding conventions. <br>
**Expected_Program**: The expected COBOL program code that adheres to the requirements specified in Cobol_Eval. <br>
**input_file_names**: A list of input file names required for the program. <br>
**output_file_names**: The name of the output file(s) expected to be generated by the program. <br>
**inputs**: A JSON object containing the sample input data for the input files. <br>
**outputs**: A JSON object containing the expected output data for the output files. <br>
 
### Completion_Set
 
**Program_name**: The name of the COBOL program or task being evaluated. <br>

## Dataset Creation

### Curation Rationale
The COBOLCodeBench Dataset was created to evaluate and improve Large Language Models (LLMs) for COBOL, a key language for legacy systems in finance and banking.<br>
It addresses the lack of COBOL benchmarks by adapting challenging problems from BigCodeBench-Hard to COBOL's syntax <br> 
and enterprise use cases like financial calculations and data processing. 

### Source Data

#### Data Collection and Processing

- Adapted from 145 problems in BigCodeBench-Hard, we've selected 45 programs that are relevant to COBOL's traditional enterprise domains.
- The Problems focus on enterprise use cases: financial calculations, data processing, and report generation.
- The Source problems, originally in Python, were translated to COBOL based on its structural requirements.
- GNU COBOL was used as the target dialect for compatibility and accessibility.
- Reference COBOL programs were manually written and refined for evaluation.
